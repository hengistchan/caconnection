## Current engineering conclusion

The implementation and Gate 1 dual-subscription discovery have passed. It
would still be incorrect to conclude that the cellular gateway architecture as
a whole has passed: full ordinary/long-message inbound routing, outbound
routing, and unmanaged HyperOS background reliability remain incomplete.
The current real-OTP subset has passed on both SIMs for both target variants
under the permission and managed-runtime prerequisites documented below.

The first process-absent test produced a concrete HyperOS blocker: the system
received a SIM2 service/verification SMS and generated `SMS_RECEIVED`, but
skipped `SmsReceivedReceiver` at broadcast enqueue with reason
`MIUI Permission Skip`. The package was installed, enabled, not force-stopped,
and held `RECEIVE_SMS`; this is therefore a current OEM background-policy
failure, not an absent telephony broadcast.

At **2026-09-12 12:22**, the user manually enabled HyperOS auto-start for
`CA Gateway POC 36`. The corresponding device state changed from
`MIUIOP(10008): ignore` to `MIUIOP(10008): allow`. A new process-absent
baseline was established at 12:23:53 with the package still `stopped=false`,
the receiver enabled, and two existing inbound events. The post-change receive
retest failed at **12:24:31**: another SIM2 service/verification SMS generated
`SMS_RECEIVED`, but HyperOS again skipped the manifest receiver with
`MIUI Permission Skip`. The SMS permission page showed `Always allow`, and the
auto-start AppOp remained `allow`.

Framework inspection established that `MIUI Permission Skip` is generated by
the Xiaomi `OP_READ_NOTIFICATION_SMS` AppOp (`MIUIOP(10018)`) when a
`SMS_RECEIVED` intent is tagged `miui.intent.SERVICE_NUMBER=true`. Android
`RECEIVE_SMS` and HyperOS auto-start (`MIUIOP(10008)`) are separate checks and
were insufficient on their own.

After op 10018 was allowed, process-absent real OTP delivery passed for target
SDK 36 on both SIMs. Android started the app specifically for the manifest
receiver, and the resolver persisted the correct subscription/slot with HIGH
confidence.

The targetSdk 37 APK update retained Room data and Android permissions, but
HyperOS permission reconciliation reset op 10018 to ignore. The first
post-update SIM1 OTP was therefore skipped immediately. After restoring and
stability-checking op 10018, a second targetSdk 37 SIM1 OTP was delivered and
persisted in 2.309 seconds. This source did not exhibit the anticipated
multi-hour Android 17 delay, but one source is not proof for all OTP
classifications.

The non-default receiver path is therefore technically viable on this exact
device under explicit provisioning, but it is not yet deployment-safe:
`MIUIOP(10018)` must be verified and potentially restored after every install
or update. A user-accessible, non-ADB provisioning route has not yet been
proven.

A later SIM2 service-number SMS was skipped with `Greezer Denial` after
HyperOS froze the process that had been started by the preceding successful
SMS. Per the user's 2026-09-12 direction, the remainder of this POC assumes a
managed runtime that prevents background process freeze/kill. This narrows the
Phase 1 evaluation; it does not prove unmanaged HyperOS background
reliability.
